# Alatyr — ретранслятор AmneziaWG с раздельной маршрутизацией

(Раньше назывался re-vpnator. `relay-data.json` от старой версии подхватывается
автоматически: при первом запуске он копируется в `alatyr-data.json`, старый
файл остаётся на месте.)

Один исполняемый файл. Внутри себя подключается к вашему AmneziaWG-серверу
(конфиг AWG 1.0 / 1.5 / 2.0 / 3.x), сам поднимает AmneziaWG-«сервер» для своих
пользователей (AWG 1.0, 2.0 и 3.1) и **сам решает для каждого соединения**:
пустить его через VPN-туннель или напрямую с этой машины — по спискам доменов
и подсетей. Клиентам ничего настраивать не нужно.

```
                                            ┌─► AWG (vpn.conf) ──► ваш VPN-сервер ──► интернет   (сайты из списков)
 телефон/ноутбук ──AWG 1.0/2.0/3.1──► Alatyr┤
                     UDP (случайные порты)  └─► напрямую с IP этой машины ──► интернет           (всё остальное)
```

- **Ничего не меняет в системе**: никаких TUN-интерфейсов, маршрутов, DNS. Весь
  сетевой стек — в памяти процесса (userspace). Права администратора не нужны.
- Раздельная маршрутизация по подпискам (gfwlist, российские списки, подсети
  Telegram, свой URL) и своим спискам; три режима, включая «всё через VPN, как
  раньше». Всё настраивается в веб-морде — см. «Маршрутизация».
- Веб-интерфейс: пароль администратора, пользователи, `.conf`, ссылка `vpn://`
  и QR-код.
- Хранилище — один JSON-файл. Без баз данных.
- Плюс `awg-tester` — утилита, которая сама подключается по конфигу и проверяет,
  что туннель реально работает.

## Быстрый старт

1. Положите рядом с бинарником ваш конфиг апстрима `vpn.conf` и `config.yaml`
   (пример в репозитории).
2. Запустите:
   ```sh
   ./alatyr --config config.yaml          # macOS / Linux  (или ./run.sh)
   alatyr.exe --config config.yaml        # Windows        (или run.bat)
   ```
3. Откройте `http://<IP-этой-машины>:8080/`. При первом открытии появится экран
   «Первый запуск»: пароль администратора, внешний адрес для конфигов и для
   каждого протокола — включён ли он, внутренний UDP-порт и внешний порт
   (см. «Порты и проброс через роутер»). Всё это потом меняется в карточке
   «Настройки подключения».
4. «Новый пользователь» → имя → протокол → «Создать». Откроется окно с QR-кодом,
   ссылкой `vpn://` и кнопкой «Скачать .conf».
5. Разрешите во входящем файрволе выбранные UDP-порты (и TCP `8080` для
   веб-морды, если заходите с другой машины). Windows/macOS при первом запуске
   сами спросят разрешение.

## Порты и проброс через роутер

Чтобы юзеры подключались из интернета, пакет идёт так:

```
клиент ──UDP──► <внешний IP роутера>:<внешний порт> ──проброс──► <LAN-IP этой машины>:<внутренний порт> ──► alatyr
```

- **Внутренний порт** — UDP-порт, который слушает ретранслятор.
- **Внешний порт** — порт на роутере, именно он вписывается в `Endpoint`
  конфигов. Пусто = такой же, как внутренний.
- **Внешний адрес** — белый IP или домен (DDNS) роутера, тоже в `Endpoint`.
  Задаётся в блоке «Адрес сервера в конфигах и QR-кодах» (экран первого запуска
  и «Настройки подключения»). Кнопка «Определить мой внешний IP» подставит его
  сама. Именно этот адрес попадает в `.conf`, `vpn://` и оба QR; пока поле
  пустое, админка предупреждает, что в конфиги идёт локальный адрес страницы.
  В окне «Подключение» у юзера видно, какой `адрес:порт` зашит в его конфиг.

В админке есть карточка **«Проброс портов на роутере»**. В ней показаны LAN-IP
этой машины (куда пробрасывать) и готовая таблица правил для роутера:
протокол UDP, внешний порт, внутренний IP, внутренний порт. Там же кнопка
«Определить» внешний IP сети (разовый прямой запрос к `api.ipify.org`) и
«Вписать в настройки».

Советы:
- пробрасывайте только **UDP**; веб-интерфейс (TCP 8080) в интернет не открывайте;
- закрепите LAN-IP машины в роутере (DHCP-резервирование), иначе после
  перезагрузки он может смениться;
- если IP в WAN-настройках роутера не совпадает с определённым внешним IP (или
  он из диапазонов 10.x, 100.64–127.x, 172.16–31.x, 192.168.x) — у провайдера
  CGNAT, проброс не заработает, нужен «белый» IP;
- после смены внешнего адреса или внешнего порта юзерам этого протокола нужно
  заново выдать конфиги. Смена внутреннего порта применяется на лету, без
  перезапуска (не забудьте обновить правило на роутере).

Клиенты:

| Что выдали            | Куда добавлять                                                         |
|-----------------------|------------------------------------------------------------------------|
| `.conf` / QR «конфиг» | AmneziaWG (Windows/macOS/Android/iOS) или AmneziaVPN → «из файла / QR» |
| `vpn://` / QR «vpn://»| AmneziaVPN → «Добавить» → «Вставить ключ» или «QR-код»                  |

Для профилей **AWG 3.1** нужен клиент с поддержкой AmneziaWG 3.x (свежие
AmneziaVPN / AmneziaWG). AWG 1.0 понимают любые клиенты Amnezia; AWG 2.0 —
клиенты с поддержкой 2.0.

## Маршрутизация

Всё настраивается в веб-морде, карточка **«Маршрутизация»**; `config.yaml` эти
настройки не трогает. Хранятся в `alatyr-data.json` (раздел `routing`).

**Режимы:**

| Режим | Что происходит |
|---|---|
| Списки → через VPN, остальное напрямую (по умолчанию) | совпавшее с подписками и «Моими дополнениями» — в VPN, остальное — напрямую |
| Всё через VPN, кроме исключений | напрямую только «Мои исключения» и подписки с действием «напрямую» |
| Всё через VPN без разбора | пакетный NAT как в re-vpnator, правила не применяются; самый быстрый |

**Как решается, куда идёт соединение** (по приоритету):

1. «Мои исключения» → напрямую; «Мои дополнения» → VPN (важнее подписок);
2. подписки: подписка с действием «через VPN» важнее подписки «напрямую»,
   `@@`-исключения внутри подписки отменяют её же правила;
3. иначе — действие режима по умолчанию.

Имя сайта Alatyr узнаёт тремя способами: свой DNS на `10.66.66.1` (в конфигах
юзеров прописан он, а запросы на любой `:53` перехватываются), SNI из TLS
ClientHello / `Host` из HTTP (порты 80, 443, 8080, 8443) и SNI из QUIC Initial
(UDP 443). Поэтому решение верное, даже если браузер ходит в DNS сам (DoH).
Подсети (Telegram и т. п.) решаются по первому пакету.

DNS: имена из правил резолвятся **через туннель** (без утечки и подмены
ответов), остальные — напрямую (системный резолвер или заданные серверы).
AAAA и HTTPS-записи отдаются пустыми: сеть IPv4-only, а в HTTPS-записях
приходят ключи ECH, скрывающие имя сайта.

**Подписки.** Заготовки: «Россия: заблокированные сайты» (itdoginfo), подсети
Telegram и gfwlist включены; YouTube, antifilter (подсети / весь реестр
доменов — ~1,8 млн строк, ~300 МБ памяти) — по галочке. Можно добавить любой
URL; формат определяется сам: ABP/gfwlist (в т. ч. base64), список доменов,
`*.домен`, `.зона`, подсети и IP, hosts-файл, `domain:/full:/keyword:/regexp:`,
`DOMAIN-SUFFIX,…`. Для каждой подписки выбирается действие (через VPN /
напрямую) и как её скачивать (через VPN / напрямую). Списки кэшируются в
`lists-cache/` рядом с `config.yaml`.

**Обновление подписок.** Подписка скачивается сама, если её ещё нет в кэше: при
первом запуске, при включении новой подписки, при смене её URL. Дальше —
кнопкой «Обновить» / «Обновить все сейчас». Галочка **«Автообновление
подписок»** (по умолчанию выключена) обновляет их раз в N часов (по умолчанию
24). При ошибке скачивания остаётся прежняя версия списка.

**Изменения применяются на лету, без разрывов.** Сохранение настроек, правка
своих списков, обновление подписки и даже смена режима не трогают уже открытые
соединения: каждое доживает по тому маршруту, по которому началось (в т. ч.
через NAT после переключения из «всё через VPN» и обратно). Новые соединения
сразу идут по новым правилам. Если сайт уже открыт по старому маршруту,
достаточно переоткрыть вкладку (браузер держит keep-alive соединения).

**Тонкие настройки:** серверы DNS через туннель / напрямую; QUIC — блокировать,
если имя не прочитать (по умолчанию; браузер уйдёт на TCP) / всегда / никогда;
блокировка DoH/DoT (dns.google, cloudflare-dns, … и «канарейка» Firefox), чтобы
браузеры возвращались на наш DNS; доступ юзеров в локальную сеть этой машины
(по умолчанию запрещён); время ожидания имени сайта; размер журнала.

**Проверка и журнал.** «Проверить» — ввести домен или IP и увидеть решение и
сработавшее правило. Журнал последних соединений (юзер, куда, имя и откуда оно
взято, маршрут, правило) хранится только в памяти; размер 0 — выключен.

Пинг: шлюз `10.66.66.1` отвечает сам, ping наружу всегда идёт через VPN (для
прямого ICMP нужны права root).

## Сборка

Нужен Go (зависимости тянутся сами через go modules; если локальный Go старее
1.25, он сам скачает нужный toolchain).

```sh
./build.sh          # ./alatyr и ./awg-tester под текущую машину
./build.sh all      # dist/alatyr-<os>-<arch>/ для Windows, macOS, Linux (amd64/arm64/arm)
                    # + dist/alatyr-windows-x64.zip и -arm64.zip, готовые к раздаче
build.bat           # на Windows: alatyr.exe и awg-tester.exe
```

Сборка без CGO — получается один статический файл, веб-интерфейс вшит внутрь.

Что кладётся в дистрибутивы: бинарники, `README.md`, `config.yaml`; для
macOS/Linux — `run.sh`, `service.sh`; для Windows — `run.bat`, `run-hidden.vbs`,
`stop.bat`, `autostart-windows.vbs` и всё из `packaging/windows/`
(`INSTALL-RU.txt`, `firewall-allow.bat`), а в `config.yaml` включается
`log_file: alatyr.log` (фоновый запуск без окна). Виндовые файлы хранятся в
CRLF, `INSTALL-RU.txt` — UTF-8 с BOM (чтобы Блокнот показал кириллицу).
`build.sh all` пересоздаёт только `dist/alatyr-*`, остальное в `dist/` не трогает.

## config.yaml

```yaml
vpn: vpn.conf              # конфиг апстрима (путь относительно config.yaml или абсолютный)
http_port: 8080            # порт веб-интерфейса
# http_listen: 0.0.0.0     # 127.0.0.1 — веб-морда только локально
# public_host и ports — только начальные значения для первого запуска;
# дальше они задаются в веб-морде и хранятся в alatyr-data.json.
public_host: ""            # хост/IP для Endpoint в конфигах юзеров.
                           # Пусто = тот адрес, по которому вы открыли веб-морду
                           # (если открыли через localhost — автоопределение LAN-IP)
# ports:                   # внутренние UDP-порты протоколов. Без секции — при первом
#   awg1: 51821            # запуске каждому протоколу случайный свободный порт
#   awg2: 51822            # (20000–59999), он сразу сохраняется в alatyr-data.json.
#   awg3: 51823            # С секцией: 0 или убрать строку = протокол выключен
subnet: 10.66.66.0/24      # внутренняя сеть юзеров; .1 — сам ретранслятор (пингуется)
# dns: [1.1.1.1, 8.8.8.8]  # начальный «DNS через туннель» (по умолчанию из vpn.conf);
                           # дальше меняется в веб-морде. Юзерам выдаётся DNS 10.66.66.1
# lists_dir: lists-cache   # кэш скачанных подписок
# mtu: 1280                # по умолчанию MTU из vpn.conf
data_file: alatyr-data.json # юзеры, ключи, хэш пароля
log_level: info            # info | debug
# log_file: alatyr.log # писать лог ещё и в файл (полезно при скрытом запуске)
```


## Протоколы и параметры

При первом запуске для каждого протокола генерируются ключи сервера и случайные
параметры обфускации; они сохраняются в `alatyr-data.json` и одинаковы для всех
юзеров этого протокола.

| Протокол      | Параметры                                                                                   |
|---------------|---------------------------------------------------------------------------------------------|
| AmneziaWG 1.0 | Jc, Jmin, Jmax, S1, S2, H1–H4 (одиночные значения)                                          |
| AmneziaWG 2.0 | + S3, S4, H1–H4 диапазонами, I1 (сигнатурный пакет «под STUN»)                               |
| AmneziaWG 3.1 | как в AmneziaVPN: HeaderProtectionKey, S1–S4 ≥ 12, RandomTrailers, DisableCookies, тайминги  |

Апстрим (`vpn.conf`) может быть любой версии: поддерживаются все ключи
amneziawg-go 3.1 — `Jc/Jmin/Jmax, S1–S4, H1–H4, I1–I5, HeaderProtectionKey,
ContentPaddingAddition, RekeyAfterTime, RekeyTimeout, RejectAfterTime,
KeepaliveTimeout, MaxHandshakeAttempts, RandomTrailers, DisableCookies`.
`Endpoint` может быть доменом — при пропаже рукопожатия он переразрешается.

## Веб-интерфейс и безопасность

- Пароль хранится как **bcrypt-хэш** (`$2a$12$…`): строка сама содержит соль и
  стоимость, восстановить из неё пароль нельзя, можно только проверить.
- Сессия — HttpOnly-cookie SameSite=Strict на 7 дней (сбрасывается при рестарте);
  CSRF-защита; 5 неверных паролей подряд — блокировка IP на минуту.
- Забыли пароль: остановите сервис и удалите строку `admin_password_hash` из
  `alatyr-data.json` — при следующем открытии веб-морда попросит задать новый.
- `alatyr-data.json` содержит приватные ключи юзеров (чтобы конфиг можно было
  скачать повторно). Файл создаётся с правами `600` — не выкладывайте его.
- Веб-морда работает по HTTP. Не открывайте её в интернет; для удалённого доступа —
  `http_listen: 127.0.0.1` + SSH-туннель (`ssh -L 8080:127.0.0.1:8080 host`).
- Юзеры изолированы друг от друга, в сеть апстрима ходят только IPv4 TCP/UDP/ICMP.

## awg-tester — проверка подключения

Сам подключается по конфигу (userspace, без изменения системы) и проверяет:
рукопожатие, DNS через туннель, HTTP, что внешний IP отличается от прямого,
пинг и скорость загрузки.

```sh
./awg-tester vasya.conf                 # файл
./awg-tester "vpn://AAAC3Xja..."        # ключ AmneziaVPN
./awg-tester vpn.conf                   # можно проверить и сам апстрим
./awg-tester -download 0 -ping 50 vasya.conf
```

```
awg-tester: AmneziaWG 3.x, endpoint 192.168.1.92:51823, address [10.66.66.6], MTU 1280
  [ OK ] endpoint    192.168.1.92:51823 -> 192.168.1.92:51823
  [ OK ] handshake   in 101ms
  [ OK ] dns         api.ipify.org -> 104.26.12.205, ... (62ms, via [1.1.1.1 8.8.8.8])
  [ OK ] http        GET http://api.ipify.org/ through tunnel works
  [ OK ] exit-ip     94.228.213.240 (direct: 23.111.23.154)
  [ OK ] ping        1.1.1.1: 20/20 replies, 0% loss, avg 61ms
  [ OK ] download    10 MB in 860ms = 93.0 Mbit/s
RESULT: OK — the tunnel works
```

Код выхода `0` — всё работает, `1` — есть проваленные проверки.
Флаги: `-timeout`, `-download <MB>`, `-ping <N>`, `-ping-host`, `-ip-url`, `-v`.

Проверка маршрутизации Alatyr: `-expect-tunnel` / `-expect-direct` (можно
несколько раз) — адрес сервиса, который отвечает IP вызывающего (или просто
домен такого сервиса). Тестер сравнивает IP через туннель с IP напрямую с этой
машины, поэтому запускайте его на машине с Alatyr (или с тем же выходом в
интернет). Сервис нужно добавить в «Мои дополнения», если ждёте VPN:

```sh
./awg-tester -expect-tunnel http://ifconfig.me/ip -expect-direct checkip.amazonaws.com vasya.conf
  [ OK ] route       http://ifconfig.me/ip goes through the VPN (94.228.214.85, direct 172.235.171.74)
  [ OK ] route       http://checkip.amazonaws.com/ goes directly (109.252.26.222)
```

## Автозапуск

### Windows

Файлы рядом с `alatyr.exe`:

| Файл                    | Что делает                                                      |
|-------------------------|-----------------------------------------------------------------|
| `run.bat`               | ручной запуск в окне консоли (Ctrl+C — остановить)              |
| `run-hidden.vbs`        | запуск без окна (фоном)                                         |
| `stop.bat`              | остановить фоновый процесс                                      |
| `autostart-windows.vbs` | включить/выключить автозапуск при входе в Windows               |

Автозапуск: дважды щёлкните `autostart-windows.vbs` — в папке «Автозагрузка»
(`shell:startup`) появится ярлык `alatyr.lnk`, запускающий `run-hidden.vbs`.
Повторный запуск `autostart-windows.vbs` автозапуск удаляет.

Вручную то же самое: `Win+R` → `shell:startup` → создать ярлык на
`wscript.exe "C:\путь\к\run-hidden.vbs"`.

При скрытом запуске окна нет — включите `log_file: alatyr.log` в
`config.yaml`, чтобы видеть лог. Не забудьте разрешить `alatyr.exe` в
брандмауэре Windows (частные сети; публичные — если нужно).

Нужен запуск до входа пользователя (сервер без логина) — Планировщик заданий:
«Создать задачу» → «Выполнять для всех пользователей», триггер «При запуске»,
действие `C:\путь\alatyr.exe`, аргументы `--config C:\путь\config.yaml`,
«Рабочая папка» — папка программы.

### macOS

```sh
./service.sh install        # LaunchAgent: стартует при входе пользователя, перезапускается при падении
sudo ./service.sh install   # LaunchDaemon: стартует при загрузке, без входа (работает от вашего пользователя)
./service.sh status | logs | uninstall      # (с sudo, если ставили с sudo)
```

Создаётся `~/Library/LaunchAgents/com.alatyr.plist` (или
`/Library/LaunchDaemons/...`), лог — `alatyr.out.log` рядом с бинарником.
Если macOS ругается на неподписанный файл: `xattr -d com.apple.quarantine alatyr`.

### Linux (systemd)

```sh
sudo ./service.sh install   # /etc/systemd/system/alatyr.service, стартует при загрузке
./service.sh status
./service.sh logs           # journalctl -u alatyr -f
sudo ./service.sh uninstall
```

Сервис работает от пользователя, вызвавшего `sudo` (root не нужен — порты > 1024).

## Как это устроено

- `internal/awgconf` — парсер/генератор конфигов AmneziaWG, UAPI, профили
  протоколов, `vpn://` (base64url(qCompress(conf)), как в AmneziaVPN).
- `internal/relay` — два типа устройств amneziawg-go на in-memory TUN: клиент к
  апстриму и по одному слушателю на каждый протокол. TCP/UDP юзеров уходят в
  `internal/stack` (gVisor netstack в памяти), ICMP и режим «всё через VPN» — в
  пакетный NAT. Апстримный netstack и NAT делят адрес туннеля: netstack владеет
  портами 10000–19999, NAT — остальными.
- `internal/router` — решение по каждому потоку (правила, сниффинг, DNS-кэш),
  дозвон напрямую или через апстримный netstack, журнал и статистика.
- `internal/rules` — разбор списков и поиск (суффиксы доменов, подсети по длине
  префикса); `internal/sniff` — SNI/Host/QUIC Initial; `internal/dns` — DNS для
  юзеров с кэшем «IP → имена»; `internal/lists` — подписки и их кэш;
  `internal/app` — сборка всего вместе.
- `internal/nat` — userspace SNAT: адреса юзеров подменяются на адрес, выданный
  апстримом (`Address` из `vpn.conf`), с подменой портов/ICMP id; ICMP-ошибки
  (в т.ч. «fragmentation needed») транслируются обратно; таймауты сессий
  UDP 3 мин, TCP 4 ч (1 мин после FIN/RST).
- `internal/store` — JSON-хранилище, `internal/web` — веб-морда (вшита через `embed`).

### Известные особенности

- **IPv4-only**. В конфигах юзеров `AllowedIPs = 0.0.0.0/0, ::/0`, чтобы IPv6 не
  утекал мимо туннеля, но IPv6-трафик ретранслятор отбрасывает (приложения
  сами переключаются на IPv4).
- В amneziawg-go 3.1 есть баг: смещение под паддинг `S4` вычисляется до чтения
  первого пакета из TUN, поэтому первый пакет после старта устройства уходит без
  паддинга и отбрасывается получателем. В ретрансляторе это обойдено (TUN
  «будится» после конфигурации). У клиентов на этой библиотеке может теряться
  самый первый пакет после подключения — TCP/DNS его перепосылают, на практике
  обычно это лишь задержка первого запроса на несколько секунд.
- Смена параметров протокола = удалить `servers.<протокол>` из
  `alatyr-data.json` и перезапустить; после этого всем юзерам этого протокола
  нужно заново выдать конфиги.
